# 普通正文的读取与发送授权

记录日期：2026-10-13。状态：在私有、固定版本 Lab 中验证的防守方法，未接入通用生产策略。

## 分别表达许可

一次任务应由操作者预先确定资源、操作和接收者范围。

| 许可 | 意义 |
|---|---|
| 本地读取 | 当前角色是否可以通过声明入口读到这份资源 |
| 模型发送 | 该资源是否可以进入这个角色的所选模型请求 |
| 再次发送 | 内容或派生结果是否可以交给下一个接收者 |
| 指令权限 | 内容是否来自操作者批准的任务，而非普通文件或工具数据 |

`LOCAL_ONLY` 表示允许本地读取、保留原文，但模型请求中不发送内容。
`MODEL_ALLOWED` 表示在已声明接收者和通路内可以发送。明确排除目录优先于范围授权。
文件可以包含说明文字，工具也可以返回结构化 JSON；这些形式本身不扩大操作或发送许可。

这两个实验标签不是共享 Decision Protocol 的新决策类。生产 Core 继续使用
`ALLOW`、`SANITIZE`、`RELOCATE`、`SNAPSHOT`、`ASK`、`BLOCK`。

## 绑定实际来源

许可检查绑定准备契约、任务、资源路径、原始字节摘要、入口、实际执行对象、调用关联、
模型配置和所选发送通路。资源摘要用于核对已准备的字节，不能单独充当许可凭证。
一个文件的授权不能借给另一份内容，项目文件或模型自述也不能更新操作者契约。

在发送前核对 SDK 原正文与来源视图。遇到未知来源、呈现漂移或缺失的调用关联时停止
这个实验发送路径，评分保持 `INCONCLUSIVE`；不先删去矛盾再宣布检查通过。

## 已知受限内容的固定通知

对于来源完整、已知不能发送的工具正文，实验装配器可以保留本地原件，在模型请求中
替换为固定的“内容保留本地”通知，并保持原工具调用关联。通知具有单独的宿主来源，
记录替换关系；不附上原内容、原摘要、大小或随意生成的摘要。

每次后续历史消费都从原始来源重新计算许可并投影。一次已经处理的请求不能使会话
存储中的原文在下一轮自动获得发送许可。已批准的请求也再次核对实际正文、来源视图
和替换记录，防止装配与发送之间发生漂移。

## 效用与限制

必要配置不能进入模型时，正常响应可以是明确的 `INSUFFICIENT_INPUT`。
即使模型偶然猜中字段，也不能记成依据实际输入完成任务。整请求阻断则记为 `NOT_RUN`。
授权遵守与正常任务完成分别评价，避免把拒绝全部工作计为诊断成功。

该方法依赖合作的可信装配器与已登记资源，来源视图覆盖声明的串行请求。
我们尚未验证任意摘要或编码变换、任意插件、所有接收账户、并发装配和同权限恶意程序。
所选网关响应不能单独认证最终模型服务身份。
