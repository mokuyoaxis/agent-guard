# 数据流观察：从本地读取到模型请求

记录日期：2026-10-13。依据：本项目 10 月 11—13 日的合成文件、请求捕获和来源核对实验。
目标是帮助防守方定位内容经过的边界，以及哪些事实仍无法观察。

## 观察链条

| 阶段 | 可核对的证据 | 推断边界 |
|---|---|---|
| 目录枚举 | 声明目录、发起者、时间与数量 | 不证明文件内容被读取 |
| 内容读取 | 实际工具或文件 API、范围、字节数与摘要 | 不证明内容进入模型上下文 |
| 上下文导入 | SDK 序列化字段、内容摘要与资源来源 | 不证明请求已发送 |
| 发送 | 交给所选传输函数的实际正文及发送结果 | 不认证上游转发或存储 |
| 接收 | 独立接收端提供的同正文确认 | 本机回环确认只覆盖本机接收端 |

声明观察点需要具体到入口和阶段。原生 Read、受控后台校准器、插件、模型网关与
服务端是不同的发起者。只扫描最后回答，会遗漏工具结果和后续历史中的内容。
客户端可见的 reasoning 文本也只代表 SDK 暴露的块，不等于完整内部推理。

## 我们核对到的有限事实

10 月 11 日，在 DSH 0.2.0-rc.2 与 Node Kimi Code 0.42.0 上各运行一次受控
“后台读取、随后丢弃内容”的校准，共四次真实模型请求。两边各记录一次合成目录枚举和
一次文件读取，任务输出均通过；SDK 正文与实际发送正文逐字节相同，声明的家目录标记
没有进入请求。这验证了读取与导入可以分别观察。

另有主动导入的校准把同类合成内容明确追加到请求中，观察器能够记录该差异。
这些后台动作由实验控制器主动安排，不能解释为发现客户端自发扫盘。

10 月 12 日的 DSH 原生 read-result 开关对照中，普通合成正文在两种状态下都进入
后续请求；已知形状的合成凭据在开启状态的工具返回边界被脱敏。现有文本规则处理的
是已知敏感值；普通项目内容是否可以发送，需要单独表达授权。

## 防守侧的实现约束

在可信装配器中绑定实际资源、工具调用和最终发送正文，保存原始正文与经过策略处理的
正文之间的关系。对文件 API 的切片读取，核对实际范围和对应切片，避免把预读当作
完整文件读取。每次后续请求也重新核对来源，不能只检查首次消费。

缺少读取记录而接收侧出现内容时，暴露事实仍然存在，来源链保持 `INCONCLUSIVE`。
没有找到原始标记也不能证明任意摘要、转述或编码后的内容没有外发。

现有[通用 Lab](../lab/guard-lab.md)观察选定输出和回环事件；研究中的 SDK 请求捕获
仍依赖特定装配。任意文件 API、子进程、内核读取、其它传输、网关转发和服务端存储
尚未形成完整观察面。同权限控制器与受测进程之间也没有强制隔离。

相关方法见[正文发送授权](content-authorization.md)，结果与失败见
[阶段报告](../reports/blue-team-lab-2026-10.md)。
